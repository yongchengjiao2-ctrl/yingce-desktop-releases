# 分镜非流式完整返回

仅修改“生成到分镜制作”，资产提取与文案转剧本保持各自流程。

安装：`python install-storyboard-complete.py`。修改前的章节模块备份在 `backups/chapters-before-storyboard-complete-*.js`。安装后刷新桌面页面加载。

本次章节请求使用现有独立 JSON 协议 `yingce-asset-json-chat`，传入 `stream:false`、`response_format:json_object`、`max_tokens:65536`，DeepSeek 关闭思考。模型配置仅作用于请求快照，不修改用户渠道或密钥。

分镜任务只轮询状态，成功后一次读取最终结果，不订阅分镜文本事件、不展示中间正文，没有这条前端等待链路的固定完成时限。供应商、网络及后端自身的限制不由此补丁解除；失败或取消仍正常结束等待。

使用当前分镜模板，并在本次系统提示词中明确输出合同。素材目录区分已确认的真实 ID 和待确认的 @名称，场景、人物、道具均可引用；待确认项不伪造正式绑定。

真实请求测试文件在 `build/storyboard-test/`：每次保留供应商原始响应、正文、JSON（可解析时）、耗时、请求 ID、用量和校验报告。真实测试直接调用已配置供应商，未把测试结果写回用户项目。`verify-returned.mjs` 额外调用安装版本的实际分镜解析函数，并验证素材引用整理结果。

校验成功说明对应样本通过数据和格式检查，不代表未来每次请求必然成功，也不替代对镜头叙事和历史画面准确性的人工审阅。所有失败样本保留。
