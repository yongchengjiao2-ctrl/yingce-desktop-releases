## 根代理接线

```js
import {beginChapterGeneration,ChapterGenerationControl} from './chapter-generation-control.js';
async function bn(e,callbacks={}) {
 const handle=beginChapterGeneration(e.projectId,e.chapterId);
 let failure;
 try {
  return await existingGeneration(e,{
   ...callbacks,signal:handle.signal,
   onTaskUpdate(task){handle.onTaskUpdate(task);callbacks.onTaskUpdate?.(task);}
  });
 }catch(error){failure=error;throw error;}
 finally{handle.finish(failure);}
}
// 当前章节生成区独立组件，不与任务中心重复：
React.createElement(ChapterGenerationControl,{react:React,projectId,chapterId})
```

必须在模型任务创建前检查signal。createTask可能已在途：收到真实task后仍应先调用onTaskUpdate，让registry补取消；不能仅因signal已abort就丢弃taskID。当前planned runtime创建后已有onTaskUpdate再waitComplete，根代理须核实最新版本仍如此。

## 取消协议

当前章节实际使用`task-center-CCDONRL0.js`。该模块`i()`初始化，`t(taskId)`导出真实取消函数b，POST `/tasks/:id/cancel`，返回task并发出已有canvas/wallet更新事件；没有新增后端API。

- 没有taskID时取消仅abort本地，显示“已停止准备；未创建模型任务”；若在途创建后才收到taskID，自动请求真实取消并更新显示，避免孤儿任务。
- 已有taskID时先调用原task-center取消；收到status=cancelled才abort本地轮询。HTTP成功但status=running不算取消成功，显示等待后端确认，后续onTaskUpdate确认。
- 取消失败保留真实任务ID和running状态、错误与重试按钮；finish不隐藏仍运行任务。
- 完成竞态返回succeeded时显示完成，不显示取消；providerCancelStatus单独展示，不宣称上游已停止。
- 同章活跃任务不得重复start；不同章节独立；旧generation回调不能覆盖新任务；旧running更新不能复活终态。
