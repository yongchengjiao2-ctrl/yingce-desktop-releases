## 4. 实际联动链路与设置优先级

### 4.1 章节资产提取

章节源文案 → 模型选择 → 从后台读取选中完整模板 → 拼接 JSON 输出合同/覆盖清单 → 专用 `yingce-asset-json-chat` 协议 → 非流式模型结果 → JSON 与人物字段校验 → 标签覆盖/版式检查 → 双联/四联本地补齐固定排版 → 待确认候选 → 用户确认资产。

关键点：浏览器只存格式选择 ID；已编辑过的旧本机格式不参与当前后台托管流程。三类资产是一个 JSON 合同；双联/四联的固定排版不需要模型逐人重复。当前实现校验失败最多完整重试一次，不能理解为“任何情况下只调用一次”。恢复需保持提交时格式快照。

### 4.2 章节分镜生成

正文或已保存画面剧本 → 章节模型 → 所选 Skill 文本上下文 + 本次指令 → 固定分镜规则/数据合同/素材目录 → 单次文本任务 → 查询最终结果 → 本地素材和版式归一化 → 详细正文与配音检查 → 项目镜头写入。

该流程不是 Agent 工具对话：没有因为 Skill 写了工具名，就自动获得读画布、审批、视频生成和成片导出能力。当前单次任务防重复只在特定作用域成立，也不能外推为跨窗口、刷新和后端重放全都幂等。

### 4.3 三种“工作区/设置”不要混淆

1. **画布工作区**：节点、资产、任务、历史侧栏，是当前画布操作空间。
2. **账户工作区设置**：接口、默认模型、提示词偏好、存储和记忆。
3. **项目设置**：该项目的风格、画幅、默认图像/视频模型。

另有章节模型偏好 `chapterTextModel`。选择提取模型与分镜模型时会共享这项配置，用户若以为两者各自记住独立选择，体验可能不符合预期；目前应作为设计行为说明并补切换测试。

项目风格会进入提取、分镜与画布项目风格节点。修改项目风格不等于已有图片、角色卡、旧镜头会自动重新生成；需要明确哪些旧产物标记待复核。本次未验证整条风格变更失效链。

## 5. 问题清单与逐项修复任务

严重度：P1 = 可能损失剧情/错误绑定/关键功能兼容性；P2 = 明显边界缺口、提示误导或维护风险。证据等级：**复现**为运行探针得到结果；**条件冲突**为代码与现有配置构成冲突路径；**待补验**不能当成已发生故障。

### F01 · P1 · 自动引用清洗删除正常场景描述【复现】

- 位置：`shot-asset-bindings.js` → `bindPrompt`。
- 输入：`场景是废弃医院，地板有血迹。\n张三缓慢推门。`，目录中有张三。
- 实际：输出保留“张三缓慢推门”，整行场景、医院和血迹信息消失。
- 原因：对 `场景是@?[^\n]*` 的全行替换，以及相似的 `本Seq全程发生于...` 清洗，没有判断它是不是宿主生成的旧声明。
- 修复任务：只剥离结构化、可识别的宿主资产声明；不要用自然语言前缀删除创作正文。清洗前后保留可追溯差异。
- 验收：上述原句、同一行的剧情附加信息、无 @ 的场景句均保留；重复绑定仍幂等。
- 证据：`probe-results.json` A06。

### F02 · P1 · 剧本格式触发原对白校验空洞【复现】

- 位置：`storyboard-complete.js` → `validateStoryboardRows`。
- 输入有 `场次：`、`△画面` 与 `甲：这句对白必须保留。`，没有 `旁白：`。
- 实际：将一份完全不同的、格式有效的历史分镜样本送入校验，仍接受 12 行，所需对白并不存在。
- 原因：只从 `旁白：` 抽出 expected；检测到场次/画面而没有旁白时把 expected 设为空，从而跳过原文配音一致性检查。
- 修复任务：以选中的来源版本构造结构化对白/旁白清单，覆盖角色对白、旁白、OS/OV 和多行发言；校验顺序、内容和来源哈希，不能以空字符串表示“无需检查”。
- 验收：缺句、换句、增句、错序、遗漏纯对白均拒绝；无配音场景能合法通过；正文/已保存剧本两种模式分别验收。
- 证据：`storyboard-probe-results.json` B01。

### F03 · P1 · sourceBeats 只要求输出，没有真正验证画面覆盖【复现】

- 位置：`storyboard-detail-contract.js` 的提示词要求；`validateStoryboardRows` 的保存验收。
- 实际：所有行 `sourceBeats: []` 仍接受；对源文只有两条画面的输入，已有样本里超出范围的序号也未在该函数被拒绝。
- 修复任务：为本次来源建立稳定画面编号；验证每项类型、范围、覆盖全集与来源版本，允许合理跨段但禁止遗漏和伪造覆盖。编号存在还要结合内容评估，不能只查集合。
- 验收：空数组、漏画面、越界、字符串编号、旧来源编号均拒绝；合法跨段允许。
- 证据：B01、B02。

### F04 · P1 · 双联模板占用了仍在使用的角色生图槽位【条件冲突】

- 数据库：`character_turnaround` 已是凝像双联“三类资产提取 JSON”模板，`output_type=json`。
- 当前可达 `assets-BpSjmEjz.js`：角色形象/三视图生成仍以 `mode:image` 使用 `CharacterTurnaround`；没有已有角色绘图提示词时，会带上该 `promptTemplateOperation`。

### 6.2 当前提示词结构的风险

- 分镜提示词层层叠加：Skill、用户指令、PRESENTATION_RULES、COMPLETE_RULES、素材目录、OUTPUT GUIDE、DETAIL_RULES，系统提示词也可能再包含相同内容。重复合同增加长度和冲突机会；需保存最终提示词并做规则去重。
- 固定“沉稳平缓旁白”可能覆盖角色对白、喜剧、激烈争执或 ASMR 的表演需求。应把语速上限、角色音色和情绪指令拆开，依据实际叙事选择，而非所有项目统一旁白口吻。这是代码提示词风险，本次没有专门生成这些题材做对照。
- `max_tokens=65536` 与关闭 thinking 都是请求意图，不是供应商兑现保证。
- 输出标题齐全不等于导演细节有用；当前九宫格检查也偏重关键词是否出现，应增加结构化值和空间一致性检查。
- 示例不得进入人物事实、风格不得擅自改时代、参考素材不得捏造 ID，这些都有明确文字约束；仍需用包含恶意指令的正文与相近示例做回归，不能宣称文字约束即完成防注入测试。
